请深入研究这个项目，输出一份报告。

# 第一章必须是「业界口碑」
先回答"业界是否认可它"，再决定报告重心。证据取自：使用与采用信号（star/fork/下载量/依赖方/生产案例）、外部评价与批评、近 30 天社区动态（call skill:last30days）。
明确写出判定——**已获认可 / 小众但成立 / 未获认可**——并给出支撑数字。认可度证据不足时，把"声量接近零"本身作为结论报告。

# 后续章节的主次由判定决定
其余章节固定顺序为：核心卖点/技术力 → User Story → 架构模式 → 工作原理。
- 已获认可 → 按上述顺序正常展开。
- 未获认可 → 报告主体是"为什么没被认可、还值不值得看"：细节章节压缩成一份能解释成败的内部实现摘要，不展开无关设计，并写出什么证据会改变这个判定。

# 判定的边界
项目自评的指标、自举证明、营销对比页只算"项目主张"；内部工程规模（测试量、CI、文档量）不等于外部认可。两者与外部证据冲突时，以外部证据为准。
